# Kafka Schema Registry with Spring Boot - Project Documentation

## 1. Infrastructure Setup (Docker)
The project relies on a Confluent-based infrastructure managed via `docker-compose.yml`:
	Zookeeper & Broker:** The core backbone for Kafka messaging.
	Registry:** Runs on port `8081`. It is responsible for managing Avro schemas, ensuring compatibility, and handling serialization/deserialization.
    Control Center:** Provides a UI on port `9021` to monitor topics, view registered schemas, and track message flow.

* **Avro Plugin:** The `avro-maven-plugin` is configured to automatically generate Java POJOs from `.avsc` files located in

## 4. Application Configuration (application.properties)
The project is configured to communicate with the registry as follows:
* **Serializer/Deserializer:** Uses `KafkaAvroSerializer` for the Producer and `KafkaAvroDeserializer` for the Consumer.
* **Registry URL:** Set to `http://127.0.0.1:8081`.
* **Specific Avro Reader:** `spring.kafka.consumer.properties.specific.avro.reader=true` is set to ensure the Consumer automatically maps incoming messages to the generated `Employee` class.


	spring.application.name=schema-registery-avro

	topic.name=springtboot-schema

	server.port=8181

	spring.kafka.bootstrap-servers=127.0.0.1:9092

	spring.kafka.producer.key-serializer=org.apache.kafka.common.serialization.StringSerializer
	spring.kafka.producer.value-serializer=io.confluent.kafka.serializers.KafkaAvroSerializer
	spring.kafka.producer.properties.schema.registry.url=http://127.0.0.1:8081

	spring.kafka.consumer.group-id=javatechie-new
	spring.kafka.consumer.key-deserializer=org.apache.kafka.common.serialization.StringDeserializer
	spring.kafka.consumer.value-deserializer=io.confluent.kafka.serializers.KafkaAvroDeserializer
	spring.kafka.consumer.auto-offset-reset=earliest
	spring.kafka.consumer.properties.schema.registry.url=http://127.0.0.1:8081

	## set to ensure the Consumer automatically maps incoming messages to the generated `Employee` class.
	spring.kafka.consumer.properties.specific.avro.reader=true

## 5. Implementation Details ( producer & Controller is SAME as normal )
* **Producer:** Uses `KafkaTemplate` to send `Employee` objects. A `UUID` is generated as the message
 key to ensure uniform distribution across Kafka partitions.
* **Controller:** An API endpoint (`/kafka/sendObject`) accepts `Employee` JSON payloads and triggers the producer.
- Service Class
  public void sendEvent(Employee employee) {

       /// CompletableFuture<SendResult<String, Object>> future = template.send("springtboot-schema",message);
        CompletableFuture<SendResult<String, Object>> future = template.send("springtboot-schema", UUID.randomUUID().toString(),employee);
        future.whenComplete((result, ex) ->
        {
            if (ex == null) {
                System.out.println(" Message Send Successfully" +
                        "");
            } else {

                System.out.println(" Error while Sending Message ");
            }
        });

    }


- controller 

    
    @PostMapping("/sendObject")

    public ResponseEntity sendContrObject(@RequestBody Employee employee)
    {
        producer.sendEvent(employee);

        return  ResponseEntity.status(HttpStatus.OK).body(" message sent") ;

    }





* **Consumer:** Uses `@KafkaListener` to subscribe to the `springtboot-schema` topic.
    Messages are automatically deserialized into `Employee` objects upon receipt.
	
	
	  @KafkaListener(topics = "${topic.name}")
    public void read(ConsumerRecord<String, Employee> consumerRecord) {
        String key = consumerRecord.key();
        Employee employee = consumerRecord.value();
        System.out.println("Avro message received for key : " + key + " value : " + employee.toString());

    }

## 6. Execution & Verification Steps
1.  **Start Infrastructure:** Run `docker-compose up -d` to spin up Kafka, Zookeeper, and Schema Registry.
2.  **Build Project:** Run `mvn clean compile` to generate the `Employee` Java class.
3.  **Run Application:** Start the Spring Boot application (default port `8181`).
4.  **Test:**
    * Send a `POST` request to `http://localhost:8181/kafka/sendObject` with a valid JSON body.
    * Verify the logs in your console: `Avro message received for key: ...`.
    * Monitor the `Control Center` at `http://localhost:9021` to inspect the registered schemas and topic metrics.

*Technical Note: Always recompile the project after modifying the `.avsc` 
file to ensure the Java POJO remains in sync with the updated schema.*
